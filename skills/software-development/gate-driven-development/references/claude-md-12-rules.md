# CLAUDE.md 12 规则在 Hermes Agent 中的实施分析

## 来源
HeavySkill 6 轨迹深度分析 + 编程专家/大模型专家多轮讨论 (2026-06-05)

## 核心结论

12 条规则不应全部靠 prompt 强制——应分三层实施：

| 层级 | 方法 | 覆盖规则 | 阻止率 |
|------|------|----------|--------|
| Prompt 层 | system prompt | 1,2,3,4,7,9,10,11,12 | 60-70% |
| 工具层 | 工具约束/改造 | 5,6,8,3,12 | 85-95% |
| Agent Loop | 代码架构改造 | 4,6,9,10 | 90%+ |

## 优先级排序

| 优先级 | 规则 | 原因 |
|--------|------|------|
| P0 | 规则 8: 先读再写 | 防止最多的一类错误 |
| P0 | 规则 1: 编码前先思考 | 50-100 tokens 投资，避免返工 |
| P0 | 规则 12: 失败必须显性化 | 防止错误被吞掉 |
| P0 | 规则 3: 外科手术式修改 | 防止回归 bug |
| P1 | 规则 5: 确定性逻辑分离 | 需架构调整 |
| P1 | 规则 6: 硬性 Token 预算 | 需 agent loop 修改 |
| P2 | 规则 2,4,9,10,11 | prompt 引导为主 |

## Prompt 层实现（已写入 ~/.hermes/SOUL.md）

```
<claude_md_rules>
1. 代码生成前必须输出"前置分析"块：
   - 假设：...
   - 成功标准：...
   - 边界：...
   - 权衡：...
   未输出则后续写操作被取消。

2. 修改文件时，若未先使用 read_file 读取该文件，工具将返回 DENIED。

3. 遇到矛盾时，立即停止并输出 [CONFLICT] 消息，等待用户输入。

4. 每完成 5 个工具调用，输出 [CHECKPOINT]：已完成/剩余/阻塞项。

5. 任何工具调用失败，必须以 ERROR: 开头显式报告。
</claude_md_rules>
```

## 关键发现

### SOUL.md 是软约束
SOUL.md 中的规则会被 LLM 理解和引用，但不会被强制执行。
测试结果：Hermes 知道规则 1 的要求，但修改文件时仍跳过了"前置分析"块。

### 需要工具层强制检查
真正强制执行需要在 write_file/patch 工具中添加前置检查：
- 检查是否已输出"前置分析"块
- 检查是否已 read_file
- 检查是否有重复实现

### 规则间冲突解决优先级
1. 规则 12（错误显性化）> 所有其他规则
2. 规则 5（确定性逻辑）> 规则 2（简洁优先）
3. 规则 3（外科手术）> 规则 11（惯例优先）
4. 规则 6（Token 预算）> 规则 1（先思考）
