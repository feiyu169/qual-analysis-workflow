# 审计驱动修复工作流

## P0/P1/P2 优先级分阶段实施模式

当代码审查发现大量问题时，按优先级分阶段修复，每个阶段后启动第三方审查。

### Phase 1: 安全修复（CRITICAL + 部分 HIGH）
- Gate 1.1-1.4: JWT 密钥、管理员密码、.gitignore、Cookie 安全
- 第三方审查：验证修复不引入新漏洞

### Phase 2: 性能和安全加固（HIGH）
- Gate 2.1-2.4: N+1 查询、CORS、文件上传、速率限制
- 第三方审查：验证优化不破坏正确性

### Phase 3: 代码质量（MEDIUM + LOW）
- Gate 3.1-3.3: ORM 统一、静默吞错、依赖清理
- 第三方审查：验证测试实际测试（非 stubs）

### P0/P1/P2 后续实施
- P0: 回归修复 + 基本集成测试
- P1: CSRF 防护 + 随机密码 + README
- P2: ORM 统一 + AI 异步 + 日期过滤 + 测试填充

## 第三方审查集成模式

每个 Phase 完成后启动 delegate_task 审查：

```
Phase N 执行:
  1. 执行所有 Gate
  2. 每个 Gate: 验证 → 文档 → 标记完成
  3. 全部通过 → 启动第三方审查
  4. 审查人检查: 正确性、完整性、回归
  5. 如发现阻塞项 → 立即修复 → 重新验证
  6. 审查通过后才进入 Phase N+1
```

审查范围：
- Phase 1（安全）：验证修复不引入新漏洞
- Phase 2（性能）：验证优化不破坏正确性
- Phase 3（质量）：验证测试实际测试，模式一致
- 最终审查：跨阶段回归检查，测试计数验证，评分对比

关键规则：**Phase 之间的审查不可跳过。** 盲板系统项目有 4 轮审查，每轮都发现了前一轮遗漏的问题。
