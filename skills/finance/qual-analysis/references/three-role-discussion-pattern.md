# 三角色讨论会模式 — 投资分析技术设计

> 2026-07-01 实证验证：快手分析报告质量提升方案

## 角色定义

### 投资分析专家
- **职责**：优化投资分析思维链和逻辑链
- **关注点**：估值严谨性、数据准确性、分析深度、专业水准
- **输出**：深度量化标准、推理链设计、评分维度权重

### 编程专家
- **职责**：审核文档可行性，代码层面技术把关
- **关注点**：架构清晰、错误处理、性能预算、测试策略
- **输出**：可行性评分、接口定义建议、风险点清单

### 协调者
- **职责**：整合双方意见，给出实现技术文档
- **关注点**：方案可落地、向后兼容、可回滚
- **输出**：技术方案文档、集成方案、执行计划

## 讨论流程

```
Round 1: 各专家独立分析（并行执行）
Round 2: 协调者整合，形成方案初稿
Round 3: 各专家审核方案初稿
Round 4: 协调者按意见修改
Round 5: 最终共识
```

## 实证案例：快手分析报告质量提升

### 问题诊断阶段
- 投资专家：识别"形式合规vs实质合规"断裂
- 编程专家：定位P0-P5六个技术问题
- 协调者：整合为统一问题清单

### 方案设计阶段
- 投资专家：设计深度量化标准(L3/L4/L5)和推理链
- 编程专家：审核技术可行性，指出接口契约缺失
- 协调者：给出完整技术方案(接口定义+数据结构+集成方案)

### 关键分歧与解决
| 分歧 | 投资专家观点 | 编程专家观点 | 最终方案 |
|------|-------------|-------------|----------|
| 推理链数量 | 3条(因果+情景+反面) | 2条更简洁 | 2条(因果含情景参数+反面作为子模块) |
| 校准方法 | Bradley-Terry+贝叶斯优化 | 过于复杂 | 初期专家规则，后期引入统计校准 |
| 证伪权重 | 5%太低 | 15%+最低阈值 | 采纳编程专家意见 |

## 使用方式

```python
delegate_task(tasks=[
    {"goal": "投资分析专家: 优化思维链和逻辑链", "toolsets": ["file"]},
    {"goal": "协调者: 给出实现技术文档", "toolsets": ["file", "terminal"]},
    {"goal": "编程专家: 审核文档可行性", "toolsets": ["file", "terminal"]}
])
```

## 注意事项

1. **并行执行**：三个角色应并行工作，减少等待时间
2. **输出格式统一**：每个角色都应输出结构化文档，便于整合
3. **分歧显性化**：当专家意见不一致时，必须明确记录分歧和最终决策
4. **HeavySkill验证**：讨论产出的方案应交给HeavySkill做独立审查
