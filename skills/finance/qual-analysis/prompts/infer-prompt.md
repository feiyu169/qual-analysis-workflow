## 输出格式

请严格按照以下 JSON 格式输出：

```json
{
  "business_model": ["model_id_1", "model_id_2"],
  "constraints": ["constraint_id_1", "constraint_id_2"],
  "market": "{{market}}",
  "confidence": 0.85,
  "reasoning": "选择这些业务模型和约束条件的原因"
}
```

### 字段说明

| 字段 | 类型 | 必需 | 描述 |
|------|------|------|------|
| business_model | string[] | 是 | 业务模型 ID 列表，按相关性从高到低排序，通常 1-3 个 |
| constraints | string[] | 是 | 约束条件 ID 列表，通常 2-5 个 |
| market | string | 是 | 市场标识（us/cn/hk） |
| confidence | number | 是 | 推断置信度（0-1） |
| reasoning | string | 是 | 选择原因的简要说明 |

---

## 推断规则

### 业务模型选择规则

1. **主要业务优先**：选择收入占比最大的业务对应的模型
2. **可多选**：如果公司有多个显著不同的业务，可选择多个模型
3. **按相关性排序**：最相关的排在前面
4. **通常 1-3 个**：避免选择过多，聚焦核心业务

### 约束条件选择规则

1. **选择适用的**：只选择对公司有实质影响的约束
2. **可多选**：一个公司可能有多个约束
3. **通常 2-5 个**：避免选择过多，聚焦关键约束
4. **考虑组合效应**：有些约束组合在一起影响更大

### 置信度评估

- **0.9-1.0**：信息充分，匹配明确
- **0.7-0.9**：信息较充分，匹配较明确
- **0.5-0.7**：信息有限，匹配有一定不确定性
- **< 0.5**：信息不足，匹配高度不确定
