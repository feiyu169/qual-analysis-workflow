# Qual工作流调试与修复模式

## 调试循环（修复-审查-迭代）

当qual分析报告审查发现问题时，按以下循环修复：

```
发现问题 → 定位根因 → 修复代码 → 清checkpoint → 重跑分析 → 重新审查 → 验证
```

## 常见问题根因映射

### 估值模块问题

| 问题现象 | 根因 | 修复位置 |
|----------|------|----------|
| DCF结果为负值 | EBIT利润率用净利润(负)而非营业利润 | valuation_engine.py:178-189行 |
| WACC偏高 | 默认10%未用CAPM计算 | valuation_engine.py:123行 |
| 可比公司不当 | 硬编码抖音/Meta/拼多多 | valuation_engine.py:102-113行 |
| 净负债偏高 | 用流动资产合计而非现金及等价物 | valuation_engine.py:246-249行 |
| 情景分析与DCF不一致 | 使用单年FCF而非5年预测 | depth_enhancer.py:120-150行 |
| 翻转阈值方向错误 | 二分法方向验证逻辑错误 | depth_enhancer.py:152-203行 |

### 流程执行问题

| 问题现象 | 根因 | 修复位置 |
|----------|------|----------|
| Gate Checks未执行 | 模块路径不正确 | quality_enhancer.py导入逻辑 |
| 审查被跳过 | success=False时直接返回 | review_integrator.py:239-248行 |
| 断点恢复placeholder | 未检查内容质量 | workflow.py:962-968行 |
| 参数使用默认值 | 调用链未传递参数 | quality_enhancer.py:184-190行 |

### 数据一致性问题

| 问题现象 | 根因 | 修复位置 |
|----------|------|----------|
| 营收数据不一致 | 财报原文vs Wind结构化口径 | 辩论模块数据源不同 |
| 净利润双值 | 归母vs含少数股东 | 数据上下文未明确口径 |
| 币值混用 | RMB/HKD未统一 | 估值模块未声明币种 |

## 修复优先级

1. **P0（立即修复）**：估值模块负值、审查被跳过、Gate Checks未执行
2. **P1（重要修复）**：数据一致性、可比公司、翻转阈值
3. **P2（改进）**：洞察审计评分、占位符检查

## 修复后验证清单

- [ ] DCF估值为正值
- [ ] 情景分析与DCF差异<20%
- [ ] 可比公司为同业
- [ ] 翻转阈值方向正确
- [ ] 洞察审计非100/100
- [ ] 跨章节数据一致
- [ ] 币种统一
- [ ] 审查报告已生成
