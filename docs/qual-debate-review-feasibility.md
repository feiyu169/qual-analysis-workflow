# 实质审查引入多角色辩论的可行性评估

> 用户需求：实质审查（L2）能否引入多角色审查、形成辩论性质？
> 结论：**可行且基础设施已存在**（`debate_coordinator.py` 三角色引擎 + 超时保护），
> 但有 3 个必须解决的问题（历史卡死根因、审查锚点、收敛控制）。

---

## 一、现有基础：debate_coordinator.py（已实现，未启用）

| 组件 | 现状 |
|---|---|
| 三角色 | BULL_SYSTEM（看多分析师）/ BEAR_SYSTEM（看空分析师）/ PM_SYSTEM（投资组合经理裁决） |
| 流程 | Bull 论点 → Bear 逐条反驳+替代估值 → PM 权衡裁决（看多/看空/中性 + 数据支撑度评分） |
| 超时保护 | `llm_caller_with_timeout`（60s 线程超时，超时用 Bull 草稿兜底） |
| 调用点 | `quality_enhancer.enhance_report_quality` Stage3，但 **`enable_debate=False` 硬禁** |
| 禁用原因 | 历史卡死问题（qual-workflow-pitfalls 8.12/8.15 记录："辩论机制已知卡死"）——但超时保护已加 |

---

## 二、可行性评估

### 2.1 为什么可行
1. **代码完整**：三角色 prompt（BULL/BEAR/PM）、超时线程、结果合并（`_merge_debate_result`）都已实现
2. **与实质审查互补**：实质审查是"单向评估"（LLM 审内容找问题）；辩论是"对抗性论证"
   （Bull 立论 → Bear 反驳 → PM 裁决）——后者能发现单向审查遗漏的**立场缺陷**（如 R5 的
   "中性评级 vs 正文看多" 这类首尾矛盾，辩论中 Bear 会主动攻击）
3. **超时保护已解决历史卡死**：`llm_caller_with_timeout` 60s 线程超时 + 降级兜底

### 2.2 必须解决的 3 个问题

| 问题 | 现状 | 方案 |
|---|---|---|
| **Q1 卡死根因未完全消除** | 超时保护存在但 `thread.join(timeout)` 后线程仍可能残留（Python 线程不可强杀）；历史卡死可能来自 LLM 无限重试 | ① 复用 `create_harness_caller` 的 timeout（300s）+ 每角色独立调用；② 保留 60s 线程超时；③ **辩论总轮次上限 1 轮**（不做多轮迭代） |
| **Q2 辩论无锚点** | BULL/BEAR prompt 只有章节内容，无 Wind 锚点 → 看多/看空可能用幻觉数据 | 三个角色 prompt 统一注入 Wind canonical 锚点表 + 数据权威契约（复用 `_build_wind_anchor_table`） |
| **Q3 辩论结果如何进审查** | 原用途是"增强章节"（append 辩论洞察）；现要用于"审查发现问题" | 改输出：PM 裁决中的"看空方指出的问题"提取为审查 issues → 进 `_run_substantive_review` 的问题列表 → Patch 修复 |

### 2.3 落地设计（最小侵入）

```
实质审查 _run_substantive_review 新增第 5 项：对抗性辩论审查
  对 ch4（最近变化）/ ch5（经营）/ ch10（决策）等关键章节：
    Step1 Bull：看多论点（注入锚点）
    Step2 Bear：逐条反驳 + 替代估值（注入锚点）
    Step3 PM：裁决（看多/看空/中性 + 数据支撑度）
    → Bear 指出的"被忽略风险/逻辑漏洞/数据矛盾" → 审查 issues
    → issues 进 _repair_chapters（Patch 模式修复）
约束：
  - 仅对 3 个关键章节跑（控制成本）
  - 每角色 max_tokens=4000（辩论输出短），总 3 次调用/章
  - 超时 60s/角色，失败降级（跳过该章辩论，不阻断）
  - 锚点注入：三角色 prompt 全带 Wind canonical 表
```

## 三、成本与收益

| | 收益 | 成本 |
|---|---|---|
| 单章辩论 | 捕获单向审查遗漏的立场缺陷（首尾矛盾/看空遗漏/替代估值） | 3 次 LLM 调用（≈30-60s），仅 3 章 → 总 +3-5min |
| 全报告 | 实质审查从"挑错"升级为"对抗验证" | 可控（限制章节数） |

**价值点**：R5 的"评级中性 vs ch8 买入模板"这类问题，单向审查可能漏，辩论中 Bear 必然攻击（"你说看多却给中性？"）——这正是辩论的独特价值。

---

## 四、建议

1. **可行，建议落地**：复用 debate_coordinator 三角色引擎，注入锚点，限定 3 章，输出转审查 issues
2. **先小步验证**：单章（ch10 决策章）跑通辩论 → 看 Bear 能否发现 R5 的"中性 vs 买入"矛盾 → 再扩到 ch4/ch5
3. **风险控制**：总轮次 1 轮、每角色超时 60s、失败降级不阻断——彻底规避历史卡死
4. **与现有审查分工**：单向实质审查（深度/结论/事实/假设）+ 对抗辩论（立场/矛盾）→ 双模式互补

---

## 五、结论

**多角色辩论式审查完全可行**：基础设施（三角色引擎 + 超时保护）已存在，只需①注入 Wind 锚点、②输出转审查 issues、③限定 3 章 + 1 轮 + 超时降级。预计 +3-5min 成本换取"对抗性验证"能力，能捕获 R5 型"评级与正文矛盾"这类单向审查易漏的问题。建议先小步验证 ch10 再推广。
