# 辩论超时与降级策略重新设计

> 针对原方案"60s 超时 + 任一步超时即降级放弃"的重新评估。
> 结论：**60s 过严（推理模型思考+生成难完成）；降级=放弃（Bull 草稿顶替裁决，辩论价值全丢）。
> 改为：分层超时 + 部分成功降级 + 可配置**。

---

## 一、原方案问题（逐条）

| 问题 | 现状 | 后果 |
|---|---|---|
| Q1 60s 超时过严 | `llm_caller_with_timeout(..., 60)` | deepseek-v4-flash 推理模型：思考（reasoning）+ 生成论点 ≥500 字，60s 内常无法完成 → 频繁 degraded → 辩论形同虚设 |
| Q2 降级=放弃 | 任一步超时 `return result`，`pm_synthesis = bull_argument` | Bull 成功 + Bear 超时 → Bear 的对抗价值全丢；"降级"实际是"未完成就交差" |
| Q3 无部分成功 | 结果只有 degraded 布尔，无"哪步成功/哪步失败" | 消费者无法利用部分产物（如 Bull+Bear 成功、仅 PM 超时） |

---

## 二、重新设计：分层超时 + 部分成功 + 可配置

### 2.1 超时分层（不再单一 60s）

```
┌────────────────────────────────────────────────────────────┐
│ 层1：LLM 网络超时（harness_llm.create_harness_caller）       │
│    timeout=300s（默认，保持）——单次 LLM 调用的网络上限       │
├────────────────────────────────────────────────────────────┤
│ 层2：角色线程超时（llm_caller_with_timeout）                 │
│    默认 240s（原 60s → 放宽 4 倍）——推理模型思考+生成的兜底  │
│    可配置：DebateService(timeout=240)                       │
├────────────────────────────────────────────────────────────┤
│ 层3：辩论总预算（新增，防整体挂死）                          │
│    3 角色 × timeout，总预算 = timeout * 2.5（留有间隔）       │
│    超总预算 → 立即放弃该章辩论（标记 skip，不阻断流程）       │
└────────────────────────────────────────────────────────────┘
```

**为什么 240s**：harness_llm 网络超时 300s，线程超时必须 ≤ 网络超时（否则线程先被网络错误打断无意义）；
240s = 300s 的 80%，给网络留余量，同时给推理模型足够的思考+生成时间。
（实测参考：红队审查单次调用 182.6s 完成——240s 与之相当，辩论角色输出更短，通常 60-150s 完成。）

### 2.2 部分成功降级（不再一步超时就放弃）

```
DebateResult 新增：
  stages: {"bull": "ok"|"timeout"|"failed", "bear": ..., "pm": ...}   # 每步状态
  partial: bool        # 是否有部分成功（bull/bear/pm 不全 ok 但非全失败）
  degraded: bool       # 全失败或关键步骤失败（保留兼容）

降级策略（按成功步骤组合）：
┌──────────────┬──────────────┬──────────────┬──────────────────────────┐
│ Bull         │ Bear         │ PM           │ 处理                      │
├──────────────┼──────────────┼──────────────┼──────────────────────────┤
│ ok           │ ok           │ ok           │ 完整辩论 ✅               │
│ ok           │ ok           │ timeout/fail │ 用 Bull+Bear 自动裁决      │
│              │              │              │ （关键词：Bear 有"高估/风  │
│              │              │              │  险/漏洞" → 看空倾向）     │
│ ok           │ timeout/fail │ -            │ 部分辩论：保留 Bull 论点    │
│              │              │              │ + 标记 bear_missing        │
│              │              │              │ （消费者可只用 Bull 增强，  │
│              │              │              │  审查模式无 Bear 问题可报） │
│ timeout/fail │ -            │ -            │ 全部失败 → skip 该章        │
│              │              │              │ （不阻断流程）             │
└──────────────┴──────────────┴──────────────┴──────────────────────────┘
```

**关键变化**：
- Bear 超时不再让整个辩论作废——**Bull 论点仍可用于增强**（消费者 A）
- 审查模式（消费者 B）：只有 Bull+Bear 都成功才产生 Bear 反驳 issues；Bear 缺失时明确"该章无对抗审查"而非报错
- PM 超时用 **Bull+Bear 自动裁决**（规则判断），不退回 Bull 草稿

### 2.3 可配置（DebateService）

```python
class DebateService:
    def __init__(self, llm_caller, wind_data=None,
                 timeout=240,           # 角色超时（原 60 → 240）
                 total_budget_factor=2.5,  # 总预算 = timeout*2.5
                 retries=1,             # 每角色失败重试 1 次（harness 已有 max_retries=2，此为补充）
                 chapters=None,         # 章节白名单（审查=3章，增强=9章）
                 ):
        ...
```

- `timeout`：240s 默认，可下调（快速验证 120s）或上调（复杂章节 300s）
- `retries`：每角色失败重试 1 次（与 harness_llm 的 max_retries=2 叠加，但受 timeout 约束）

### 2.4 成本控制（防 9 章 × 3 角色爆炸）

| 场景 | 最坏成本 | 控制 |
|---|---|---|
| 审查模式（3 章） | 3 × 3 × 240s = 36min（最坏全超时） | 实际正常 3×3×120s≈18min；全超时走 skip 不阻断 |
| 增强模式（9 章） | 9 × 3 × 240s = 108min（最坏） | **可配章节白名单**（默认 9 章，可减到 5 章）+ 总预算因子 |

> 注：正常情况（非超时）每角色 60-150s，9 章 ≈ 30-45min，仍偏长——**增强模式默认建议只跑关键章（ch1/4/5/7/10）或由开关控制**。

---

## 三、与"统一"方案的关系

统一方案不变（单一 DebateService + 双消费模式），本设计只改**超时/降级的内部策略**：
- 引擎层 `llm_caller_with_timeout` 的 60s → 240s（参数化，默认 240）
- 降级从"一步超时就 return"→"记录 stages + 部分成功利用"
- DebateService 暴露 timeout/retries/chapters 配置

---

## 四、结论

**原 60s 超时 + 一步超时即降级 = 过严 + 放弃式降级，必须改**。
新设计：**分层超时（网络 300s / 角色 240s / 总预算）+ 部分成功降级（Bull+Bear 可独立利用，PM 超时自动裁决）+ 可配置（timeout/retries/chapters）**。
收益：辩论在推理模型下真正可完成（不再频繁 degraded）；部分成功也产出价值（Bull 增强可用、Bear 缺失明确标注）；成本可控（白名单 + 总预算 + skip 不阻断）。
