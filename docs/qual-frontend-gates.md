# Qual 前端闸门方案：从生成源头杜绝模板残留/空章/财年错位

> 用户核心诉求：**审查是后端（发现），问题产生在前端（生成）——必须在生成阶段设闸门根治**。
> 关键诚实结论：R6 跑的是 v2-v7 单体（run_qual_full.py），**v8 引擎（含红队审查）从未接入生成路径**，
> 后端审查对 R6 形同虚设。前端更只有格式校验（structural_check），无数值量级/空章闸门。

---

## 一、现状核查（前端/后端闸门清单）

| 阶段 | 闸门 | 现状 | 能拦什么 | 漏掉什么 |
|---|---|---|---|---|
| 前端 生成前 | prompt 数据铁律/权威契约/骨架 | ✅ 已做 | 数字改锚点、章节结构 | **估值数字必须用锚点**（未强制）；模板残留 |
| 前端 生成时 | `_generate_chapter` 后 `structural_check` | ✅ 格式校验 | 三小节/占位符/H1 | **数值量级**（1427.8 vs 73 差20倍不拦）；**空章**（24字符通过） |
| 前端 生成后 | `_write_chapters` 完整性 | ⚠️ 仅数量+字数 | 缺章 | 空章（有标题无内容） |
| 中端 组装前 | `_assemble_report` | ❌ 无闸门 | - | 模板残留/空章直接进报告 |
| 后端 终审 | v8 Gate8 红队 | ✅ 已实现 | 一切 | **R6 从未运行**（v2-v7 单体不接 v8） |

**结论**：前端只有"格式"闸门，无数值/空章/模板闸门；后端红队存在但未接到生成路径。R6 的 1427.8/187元/空章全靠**事后手动扫描**才发现——这正是"审查在后端、问题在前端"的实证。

---

## 二、方案：前端四道闸门（生成源头拦截）+ 后端接入

### 闸门 1：数值量级校验器（`quality/numeric_guard.py`）—— 新增，核心

**原理**：章节内任一财务数字与 Wind 锚点**同指标量级比对**，差 > 阈值即拦截。

```
- 提取章节所有 "数字+亿元" 模式（复用 DataAnchor._extract_data）
- 对每个数字，找 Wind 锚点中**同数量级**的指标（营收/净利/现金流/资产）
- 规则：
  - 数字与锚点任一指标同量级（0.1x ~ 10x）→ 合法（可能是某指标值）
  - 数字与**所有**锚点指标都差 >10x（如 1427.8 vs 73-81）→ **模板残留嫌疑** → P0
  - 特例豁免：百分数、年份、股本（10.2亿股）等白名单
```

**效果**：1427.8（营收锚点 73-81，差 17-19 倍）→ 立即拦截；187元 情景（无锚点可比）→ 需估值铁律辅助。

### 闸门 2：空章检测（`_generate_chapter` 后）

```
章节内容去空白后长度 < 800 字符 → 视为空章/半成品 → critical → 强制重生成
（R6 第8/9章 24/23 字符 → 秒拦）
```

### 闸门 3：生成时校验链（`_generate_chapter` 集成）

```
生成 → structural_check（格式）→ numeric_guard（量级）→ 空章检测
任一 critical → 重试（现有 3 次机制扩展：格式修正 prompt 增加"删除模板残留数值/补全内容"）
```

### 闸门 4：组装前闸门（`_assemble_report` 前）

```
11 章全部通过闸门 1-3 才组装；任一失败 → 该章标记"未通过前端闸门"，
不进入报告（或进入时报告头标注"⚠️ 第N章未通过数值校验"）
```

### 后端接入（关键）：v8 引擎成为唯一生成路径

```
run_qual_full.py → QualWorkflow.execute()（v8）
  Gate3 生成（集成闸门 1-3）→ Gate4 审查修复 → Gate5 增强 → Gate6 决策
  → Gate8 红队终审（后端兜底）
不再用 v2-v7 单体的 run_analysis 裸跑（无前端闸门）
```

## 三、估值模板残留的专项根治（R8 重跑的关键）

### 3.1 prompt 层：估值章节数值铁律
```
第7章 prompt 注入："估值章节出现的任何营收/利润/现金流数字，必须与 Wind 锚点同量级
（差>5倍即模板残留）；禁止使用锚点外任何数值；每股价值必须基于本报告总股本(10.17亿股)与
净资产(175.26亿)重算"
```

### 3.2 生成层：估值数值量级校验（闸门 1 对估值章加严）
```
估值章（ch7）：任何"当前营收/当前利润"数字 vs Wind 锚点差 > 5 倍 → P0 强制重生成
（普通章 10 倍，估值章 5 倍）
```

### 3.3 根源：LLM 训练数据模板记忆
- deepseek-v4-flash 在长上下文下会把**别的报告（美团/小鹏）的估值表**记忆进来
- prompt 无法 100% 阻止 → **量级校验是唯一可靠防线**（数值差 20 倍必然被机器拦截）

## 五、预期效果

- **1427.8/187元 模板残留**：闸门 1（量级差 20 倍）→ 生成时即拦，重试重写
- **第8/9章空章**：闸门 2（24 字符 < 800）→ 秒拦，强制补全
- **第5章财年错位**：R7-③ 财年铁律（已做）+ 闸门 1（11.4 vs 锚点 -7.76 同量级但符号不同→提示）
- **后端红队**：v8 引擎接入后，Gate8 红队成为真正兜底（R6 的教训：不接生成路径 = 形同虚设）

**核心转变**：从"生成→事后审查发现"到"生成即校验拦截（前端 4 闸门）→ 后端红队兜底"。
LLM 的统计性模板记忆无法靠 prompt 消除，但**数值量级校验是确定性的机器防线**——1427.8 与 73 亿差 20 倍，任何 LLM 都无法绕过机器校验。
