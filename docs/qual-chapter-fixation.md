# 章节内容固化方案（防止 LLM 随意生成）

> 问题：R5 报告出现 ch4 写出 `# 第5-9章`（章节重号）、ch8/ch9 整章模板泄漏——根因是
> LLM 生成章节时**结构自由**：H1 可随意创建、章节主题可漂移、小节可增删。
> 目标：把"章节"从 LLM 自由写作改为**骨架先行 + 严格校验**的结构化产出。

---

## 一、现状问题（结构自由的三处漏洞）

| 漏洞 | R5 实锤 | 根因 |
|---|---|---|
| V1 H1 可随意创建 | ch4 把 5 个变化写成 `# 第5章 管理层更替`… | `structural_check` 只查三小节，**不限制 H1 数量/层级**；`_assemble_report` 只 strip 首行 `# ` |
| V2 章节主题可漂移 | ch8 变成组合构建、ch9 变成另一公司 DCF | prompt 有 goal/contract，但**无"章节标题=固定"的硬约束**，LLM 可换主题 |
| V3 小节可增删 | 三小节有时缺失（格式重试 3 次仍失败） | 依赖 LLM 自觉遵守 `## 结论要点/详细情况/证据与出处`，无强制 |

---

## 二、固化方案：骨架先行（两步生成）+ 三层校验

### 核心思想

**不让 LLM 自由决定章节结构，而是先由程序给出固定骨架，LLM 只填充内容。**

```
Step A（骨架固定，程序控制）：CHAPTERS 定义 → 每章的固定小节清单
  第N章 {固定标题}
    ## 结论要点        （固定，3-5 条）
    ## 详细情况        （固定，子节由 CHAPTERS[chapter].sections 决定）
      ### {固定子节1}
      ### {固定子节2}
    ## 证据与出处      （固定，表格）

Step B（内容填充，LLM 受限）：prompt 明确"只填充正文，禁止改标题/增删小节/新增 H1"
  + 生成后 structural_check 升级：
    - H1 唯一性断言（只能有一个 `# 第N章 固定标题`）
    - 固定小节存在断言（`## 结论要点` 等必须精确出现）
    - 禁新增 H1 断言（内容中 `# ` 只能出现一次）
    - 章节主题锚定断言（标题含 CHAPTERS 固定标题关键词）
```

### 三层校验（生成后）

| 层 | 位置 | 校验 | 失败处理 |
|---|---|---|---|
| L1 即时 | `_generate_chapter` 后 `structural_check` | H1 唯一性 + 固定小节 + 禁占位符 | 重试（现有 3 次）+ **骨架修正 prompt**（新增：明确"你输出的 `# 第X章` 是违规的，必须删除，只保留正文"） |
| L2 组装 | `_assemble_report` | 内容内 H1 检测 → 自动降级为 H2 或剥离 | 自动修复（不再放行） |
| L3 最终 | v8 Gate8 | 章节重号检测（已有）+ 固定标题校验 | FAIL（Critical） |
