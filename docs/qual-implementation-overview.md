## 三、三阶段关键决策速查

### 阶段 A：死循环修复核心
- **根因**：三层嵌套重试（LLM 层 × Gate4 循环 × Gate 级）× 确定性 LLM 空输出（finish=max-tokens, text=""）
- **修复**：确定性失败不重试 + shadow 单次执行 + 收敛早停 + 豁免 fail-closed + 单调守卫 + 预算 200 + deadline + 熔断可达
- **已验证**：P0-A 三项（签名保留章节号/豁免累积判据/单调守卫计数）Python 实跑真绿

### 阶段 B：数据真实性核心
- **财年语义**：章节级两级规则（ch5/7 当期断言从严、ch6/4 对比豁免）；any-fy 保留为幻觉过滤层
- **估值程序化**：current_price/shares 动态取（删 21.48/46.52/41.6）+ DCF 降级链（亏损公司走 PS）
- **财务 100% Wind**：fact_extractor 删 financial 提取 + Wind 缺失字段处置表（禁启发式回填）
- **事实表**：多财年化 + 页码/原文片段/置信度/仲裁状态字段

### 阶段 C：审查效率核心
- **去重**：跨章统一（含 data_repair 第二套）、logic 上报 1 次、占位符统一常量、锚点 10→1
- **分层触发**：静态每轮全量（回归防线）+ LLM 首轮全量/修复后仅受影响章 → 降 50-60%
- **硬约束**：C4-3 豁免 fail-closed（防缺陷1 回归）；红队 fatal 回流；预算 35 ⊂ 200

## 六、方法学沉淀（本项目的可复用经验）

1. **HeavySkill 三轮收敛审查**：v1(18 项) → v2(3 必红) → v3(7 P0)——多轨迹独立审查 + 综合审议亲自源码验证，发现单次审查易漏的缺陷（熔断器双死、幽灵模块、except 顺序）
2. **"设计写了但代码没接"是最大风险**：shadow_skip_repair、_budgeted_caller、LLM_EMPTY_OUTPUT 三处悬空接线教训 → 所有方案必须带**接线级验收**
3. **自带测试必红 = 修订未经验证闭环**：v2 的 3 个"文档代码与自身测试矛盾"是第二轮最硬证据
4. **专业评审（证券专家）补架构盲区**：财年语义代码化、估值程序化、Gate8 阻断化三大结构性缺口是 LLM 流水线"信任押在 prompt 文字纪律"的典型教训
5. **审查环节效率**：静态检查器便宜可每轮全量；LLM 审查贵应首轮全量+增量；区分"必须精确"（财务/估值）与"可容忍近似"（行业规模）数据
