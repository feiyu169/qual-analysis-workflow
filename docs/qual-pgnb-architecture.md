## 二、根因分析（为什么现有防线不够）

### 现有防线（已部署，均正确但被动）
1. **prompt 注入锚点表**（workflow.py:972-998）：Wind 三表 + 数据铁律 + 财年铁律——LLM 仍幻觉
2. **生成后 ADVC 清洗**（anchor_repair）：只修"可签名错位"（×10/prefix_drop），**对纯幻觉（14.0 vs 767.20）无签名 → T3 只标注不修**
3. **修复循环校验器回滚**（_numeric）：拦截幻觉但**消耗预算返工**
4. **Gate8 救援 sweep**：最终闸门兜底，但报告已带降级

### 根因（三层）
- **生成层**：LLM 对财务数字的"引用"本质不可靠——prompt 无论怎么写，LLM 都会按自己的统计规律输出数字（幻觉是生成模型固有属性，非提示工程可根治）
- **数据层**：facts 提取的字段映射误报（问题 3）产生噪音，但不直接致幻
- **修复层**：审查-修复循环以"LLM 修 LLM"为手段——对幻觉数字，LLM 修复器同样不可靠（之前会话实证"修复循环 LLM 反复产错"）

## 三、架构根治方案：数字回填管线（Post-Generation Numeric Binding, PGNB）

**核心思想**：把"财务数字"从 LLM 的写作职责中**彻底移出**——LLM 只负责生成结构/表述/逻辑，数字用**占位符**表示，生成后由**程序按锚点回填**。这与双专家"数字是引用不是创作"结论一致，但更进一步：**不只是校验，而是直接回填**。

### 3.1 占位符机制（writing with placeholders）

```
LLM 输出示例（当前）："公司营业收入14.0亿元，较上年增长显著。"
PGNB 后 LLM 输出："公司营业收入[{{营收}}]亿元，较上年增长显著。"
程序回填："公司营业收入767.20亿元，较上年增长显著。"
```

**实现**：
1. **prompt 增加占位符语法**：`[{{指标名}}]` 表示"此处由系统按 Wind 锚点回填，禁止写数字"
2. **锚点表注入**（已有）+ **回填表注入**（新增：指标名 → 各财年值）
3. **生成后回填器**（`numeric_binder.py`）：
   - 扫描 `[{{X}}]` 占位符 → 查锚点表 → 替换为最新财年值（或按上下文财年）
   - 无锚点的占位符（如运营数据）→ 保留为 `[数据待核]` 或由 facts 回填
4. **校验器保持不变**（validate_chapter_any_fy 仍拦截漏网的裸数字）——双保险

### 3.2 为什么 PGNB 根治（vs 现有防线）

| 方案 | 对纯幻觉（14.0 vs 767.20） | 预算消耗 | 依赖 LLM 可靠性 |
|------|--------------------------|---------|----------------|
| prompt 铁律（现有） | ❌ LLM 仍幻觉 | 高（返工） | 高 |
| ADVC 签名修复（现有） | ❌ 无签名不修 | 中 | 低（确定性） |
| 修复循环回滚（现有） | ✅ 拦截但返工 | 极高（35 次耗尽） | 高（修复器也幻觉） |
| **PGNB 回填（方案）** | ✅ **根本不产生幻觉数字** | **低（无返工）** | **零（数字全程序）** |

**关键收益**：
- 幻觉数字**从源头消失**（LLM 无数字可写，只写占位符）
- 修复循环**不再为数字返工**（值类问题归零）→ 预算留给真正的逻辑/结构问题
- 财年标注（问题 2）同步解决：占位符自动带 FY 标注（回填器输出 `FY2025 营收 767.20 亿`）
- 跨章矛盾（问题 4）缓解：所有章节的同一指标引用同一锚点 → 天然一致

### 3.3 占位符回填器设计（`tools/finance/qual_v8/numeric_binder.py`）

```python
"""数字回填器（PGNB 架构层）——LLM 写作占位符 → 程序按锚点回填

职责：
1. 扫描章节中的 [{{指标}}] 占位符
2. 查 DataAnchor 锚点表，按上下文财年回填
3. 无锚点占位符 → 保留 [数据待核] + warning（不静默）
4. 回填后仍跑 validate_chapter_any_fy（双保险）
"""
PLACEHOLDER_RE = re.compile(r"\[{{([^}]+)}}\]")

def bind_placeholders(content: str, anchor, chapter_num: int) -> tuple[str, list[str]]:
    """回填占位符。返回 (回填后内容, 未解析占位符列表)"""
    def _resolve(metric: str) -> str | None:
        # 指标名 → 最新财年锚点值（带 FY 标注）
        pts = anchor.get_metric_points(metric)
        if not pts:
            return None
        latest = pts[-1]
        return f"{latest.value:.2f}"
    ...（扫描替换）
```

### 3.4 接入点（最小侵入）

```
_generate_chapter（workflow.py:1232 后）
  → content = bind_placeholders(content, anchor, chapter_num)  # PGNB 回填
  → 校验器照常（拦截漏网裸数字）
review_repair_loop._repair_chapters（sweep 后）
  → 修复后再次 bind（LLM 修复器也可能写占位符）
Gate8 救援 sweep
  → 最后再 bind 一次（终局兜底）
```

## 四、配套修复（与 PGNB 并行，解决剩余问题）

### 4.1 字段映射误报修复（问题 3）
- `data/mapping.py:164`：`required_fields = ["营业总收入", "营业利润", "净利润"]` 改为 **canonical 键** `["营业收入", "营业利润", "归母净利润"]`（canonical 化后键名）
- 或 `validate_schema` 入参改为"先 canonical 化再校验"

### 4.2 财年标注强化（问题 2）
- PGNB 回填自动带 FY 标注（主要修复）
- 保留 `validate_fiscal_references` 作为兜底（LLM 若写裸历史值仍拦截）

### 4.3 修复循环预算优化（问题 6）
- 当前 Gate4 子预算 35 次（gate4.py:283）→ 改为**按章节数比例**（如 `max(35, 11 × 5)`）或**每轮上限**（3 轮 × 12 次/轮）
- PGNB 后值类问题归零 → 预算压力天然下降（修复循环只处理逻辑/结构）

### 4.4 日期锚点模糊词（问题 5）
- prompt 增加"禁止使用'当前/目前/最近'等模糊时间词，必须用具体年份（FY2025）"
- `date_anchor_check` 已存在，保留拦截

## 七、结论

**LLM 章节生成大量问题的根源是"让 LLM 承担了它天生不可靠的任务——财务数字引用"。** prompt 铁律、生成后校验、修复循环回滚都是"在 LLM 犯错后补救"，必然伴随预算浪费与报告降级。**架构级根治 = 数字回填管线（PGNB）**：把数字从 LLM 写作职责中移出，用占位符 + 程序回填替代——LLM 只写结构，数字全部由锚点程序化注入。这不是让 LLM"更听话"，而是**改变任务分配**（与双专家"数字是引用不是创作"、ADVC"值类问题移出 LLM 职责"一脉相承的第三层深化）。

heavyskill K=8 独立审查确认方向正确但指出 v1 只覆盖"遵守规则的输出"（根治性 4/10）——v2 升级（派生指标程序化 + 裸数字硬拦截）已按三条建议落地，见 §八。

## 八、HeavySkill K=8 审查结论与 v2 升级（2026-08-22）

### heavyskill 审查评分（heavyskill-pgnb-review.json，8 轨迹无截断）
**PGNB 根治性 4/10、需求满足度 4/10、方案完整性 5/10**——"正确方向上的结构性缓解，但不是从根源杜绝"。

核心缺口（4 轨迹共识）：
1. **裸数字未拦截**：回填器只处理占位符，LLM 写裸数字（14.0）仍靠 prompt 配合
2. **派生指标缺失**：7 个绝对额锚点不覆盖毛利率/净利率/ROE/同比/CAGR/估值——投资分析真正依赖的指标 LLM 仍自算/幻觉
3. **占位符逃逸/语义错配**：`[{{毛利率}}]` 误配营业收入、`[数据待核]` 进终稿、回填格式、单位/财年/别名治理
4. **比例/增速表述仍 LLM 生成**："绝对额正确 + 比例虚假"更隐蔽
