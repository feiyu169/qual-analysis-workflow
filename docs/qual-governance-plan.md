## 二、治理框架：四层防线

### 防线 1：数据契约层（源头治理）

**原则**：所有财务数据必须通过 Financials 契约传递，禁止 dict[str, Any] 直传。

**措施**：
1. **Wind 适配器强制化**：`wind_to_financials()` 作为唯一入口，缺失字段 fail-fast
2. **Canonical key 统一**：`canonical.py` 作为唯一真源，禁止绕过
3. **数据血缘追踪**：每个 Financials 字段记录 `source`/`timestamp`/`confidence`
4. **输入校验器扩展**：覆盖所有关键参数（WACC/g/PS/PB/EV-Rev/汇率）

**验收标准**：任何财务数据可追溯到 Wind API 返回值。

### 防线 2：估值引擎层（逻辑治理）

**原则**：估值计算必须通过 ValuationArbiter 唯一出口，禁止 Gate 自行计算。

**措施**：
1. **ValuationArbiter 唯一出口**：gate5.py 只消费 Arbiter 结论，不自行计算
2. **DCF 适用性判断**：亏损公司 + OCF 为负 → DCF 不适用，自动降级
3. **翻转阈值数学验证**：所有翻转点必须 ≤ 当前值（方向验证）
4. **评级-目标价映射**：`_derive_rating()` 自动推导，消除人工判断

**验收标准**：任何估值输出必须包含 `rating` + `method` + `reconciliation`。

### 防线 3：检查前移层（流程治理）

**原则**：致命问题必须在 Gate 5-7 拦截，不能到 Gate 8 才暴露。

**措施**：
1. **Gate 5 增加估值一致性检查**：DCF vs 可比公司偏差 >40% → 警告
2. **Gate 6 增加评级-目标价校验**：评级与上行空间不一致 → 警告
3. **Gate 7 增加跨章数据校验**：关键指标跨章引用不一致 → 警告
4. **Gate 8 降级为"最终确认"**：不再承担"发现新问题"职责

**验收标准**：Gate 8 的 fatal 来自 Gate 5-7 的 warning 升级，而非新发现。

### 防线 4：回归测试层（长效治理）

**原则**：每个修复必须有对应的回归测试用例，防止复现。

**措施**：
1. **Fatal 回归错题库**：4 个已暴露 fatal 固化为测试用例
2. **多股票回归集**：小鹏（港股亏损）+ 协鑫能科（A 股盈利）+ 扩展到 5-10 只
3. **Gate 8 零 fatal 验收**：连续 N 只股票 Gate 8 零 fatal 作为升级标准
4. **数据血缘审计**：每次运行后自动检查数据一致性

**验收标准**：回归测试覆盖率 ≥ 90%，新增标的首过率 ≥ 95%。

## 五、与 dayu-agent 的差距收敛

| 维度 | dayu | qual v10 | 优化后 | 差距 |
