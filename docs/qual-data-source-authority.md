# 数据源优先级与归一性评审报告（架构确认）

> 评审问题：数据的**归一性**与**真实性**应如何设计？"事实提取的数据源优先级 =
> **财报 > Wind > anysearch/tavily**"是否正确？
>
> 结论：**方向正确，但需补两个关键澄清**——①"权威"分两个维度（内容真实性 vs 数值锚定），
> ②现有代码实际是"财报供内容、Wind 供数值、搜索供补充"的分工，而非简单优先级链。

---

## 一、核心判断

| 用户假设 | 评审结论 |
|---|---|
| 数据源优先级：财报 > Wind > anysearch/tavily | **真实性维度 ✅ 正确**：财报（一手披露）> Wind（二手整理）> 搜索（三手观点） |
| 但需补充 | **数值锚定维度 ⚠️ 以 Wind 为唯一真源**（结构化+财年明确+可机器校验），财报提取做交叉印证 |
| 归一性 | ✅ 已落地：`canonical.py` 单源契约，所有来源归一到 canonical 键 |

**一句话**：真实性上"财报最可信"，但**数值一致性上"Wind 最适合当锚"**——因为财报原文提取有
LLM 误差/财年错位风险（R5 实锤），而 Wind 是结构化、财年标签明确、可程序化校验的。两者不是
"谁替代谁"，而是**分工**：财报供内容与运营事实，Wind 供财务数值锚点，搜索只做补充。

---

## 二、两个维度要分开

### 维度 1：内容真实性（哪个来源最接近事实）

```
一手：财报原文（公司自己披露，MinerU 解析）
  ↑ 最真实，但：原始文本、含对比期、财年需推断、LLM 提取有误差
二手：Wind（第三方整理自财报）
  ↑ 结构化、财年明确，但：口径可能调整（IFRS/Non-IFRS）、有时滞、偶有异常值
三手：anysearch/tavily（互联网搜索）
  ↑ 覆盖新闻/行业/观点，但：不可作为财务数值依据
```

### 维度 2：数值锚定（哪个来源适合做"标准答案"做机器校验）

```
Wind canonical：✅ 结构化、canonical 键、_year_labels 财年标签、可 1% 容差程序化校验
财报提取：     ⚠️ 可作为交叉印证（仲裁后一致才引用），但提取误差/财年错位使其不适合当锚
搜索：         ❌ 完全不适合数值锚定
```

**这就是 R5 数据矛盾的本质**：当时把"财报提取的事实表"（FY0/混入对比列）当成了与 Wind 平级的
"权威"，两套并存无仲裁 → LLM 各章自选 → 三套收入/四套现金流。修复（P0-B2）正是确立
**"Wind 数值锚 + 财报内容源 + 仲裁"**的分工。

## 三、现有代码的实际实现（数据源优先级现状）

### 3.1 数据采集层（`workflow._collect_data` / `data_collector.py`）

```python
filing_source: "filing" | "fallback" | "unavailable"   # 财报
wind_source:   "wind"   | "fallback" | "unavailable"   # Wind
search_results: list[SearchResult]                      # anysearch/exa/tavily（可选）
data_quality = high (filing+wind) | medium (其一) | low（data_context.py:230）
```

**现状**：财报与 Wind 是**并列双源**（各自 source 标记），搜索是可选第三源。没有显式的
"财报 > Wind > 搜索"优先级链——优先级体现在 `_build_chapter_prompt` 的**注入顺序与约束**。

### 3.2 章节 prompt 注入顺序（`workflow._build_chapter_prompt`，真实数据流）

```
1. 事实表（财报提取，P0-B2 仲裁后）      ← 内容/运营事实源
2. 财报原文片段（仅事实表不可用时）      ← 内容补充
3. Wind 摘要（结构化数据）              ← 数据参考
4. 数据铁律（Wind 锚点 FY 最新财年）    ← 数值真源（禁止改动/矛盾作废）
5. 搜索摘要（anysearch/tavily）          ← 外部补充
```

**实际优先级语义**：
- **数值**：Wind 锚点铁律 > 事实表（仲裁后一致才引用；冲突以 Wind 覆盖）> 搜索（不参与数值）
- **内容/运营**：事实表（财报提取）> 财报原文 > 搜索
- **行业/外部信息**：搜索（财报/Wind 无此信息）

### 3.3 与用户假设的对照

| 用户假设 | 现状 | 差异 |
|---|---|---|
| 财报 > Wind > 搜索（事实提取） | 财报供**内容/运营**；Wind 供**数值锚** | 财务数值上 Wind 优先（因可校验） |
| 归一性 | canonical.py 已统一 | ✅ 一致 |
| 真实性 | 财报一手 > Wind 二手 > 搜索三手 | ✅ 一致（内容维度） |

## 四、关键架构结论（评审输出）

### 4.1 数据源优先级（最终定义）

```
┌─ 内容真实性优先（谁披露谁权威）─────────────────────┐
│  财报原文（一手）→ Wind（二手整理）→ 搜索（三手观点） │
└──────────────────────────────────────────────────┘
┌─ 数值锚定优先（谁可校验谁当标准）───────────────────┐
│  Wind canonical（唯一真源）→ 财报提取（印证）→ 搜索 ✗ │
└──────────────────────────────────────────────────┘
```

**分工矩阵**：
| 数据类别 | 内容真实源 | 数值锚定源 | 冲突仲裁 |
|---|---|---|---|
| 财务数值（收入/利润/现金流/资产） | 财报（披露） | **Wind（唯一真源）** | 同财年偏差≤1% 保留财报值；>1% 以 Wind 覆盖；异财年财报降级为参考（P0-B2 已实现） |
| 运营/定性（MAU/付费/IP/治理/风险） | **财报事实表（唯一源）** | Wind 无此数据 | 财报为准，交叉验证 |
| 行业/市场/新闻 | 搜索（anysearch/tavily） | 无 | 引用标注来源，不参与数值 |

### 4.2 归一性（已落地）

- **canonical.py 单源契约**：所有来源（Wind 原始列名/财报提取/检查器期望键）→ canonical 键
- **归一发生在数据进 LLM 之前**（`canonicalize()`），LLM 只见 canonical 形态
- **财年维度**：Wind `_year_labels` 为锚，事实表 `fiscal_year` 对齐（P0-B1 已实现）

### 4.3 现有代码的"优先级"载体与缺口

- ✅ `data_quality`（filing+wind 双源可用性）—— 已有
- ✅ `_reconcile_facts_with_wind`（数值仲裁）—— 本轮已实现
- ✅ `canonical.py`（归一）—— 本轮已实现
- ⚠️ `AuthorityResolver`（quality/authority_resolver.py）—— **是"流程层级"权威**（L1 审计修复/L2 质量管道/L3 监督），
  不是"数据源优先级"；两者不要混淆。若要显式数据源优先级，建议新增 `SourceAuthority` 枚举
  （filing=primary / wind=primary_numeric / search=supplementary）或在 `_build_chapter_prompt` 顶部注释声明
- ⚠️ 搜索源（anysearch/tavily）在 R5 实际运行中为 `None`（未启用）——当前链路事实上是"财报+Wind"双源

---

## 五、建议（小改，可选）

1. **显式声明数据源优先级**（文档级）：在 `_build_chapter_prompt` 头部注释或 `data_context.py` 加
   `SOURCE_AUTHORITY = {"filing": "content_primary", "wind": "numeric_primary", "search": "supplementary"}`
   ——把"财报供内容、Wind 供数值"的隐式分工变成显式契约
2. **搜索源启用时**：仅注入"行业/外部"章节（ch2 行业、ch7 估值参考），且 prompt 明确
   "搜索数据仅供参考，不参与财务数值"
3. **AuthorityResolver 保持现状**：它管的是质量流程层级，与数据源优先级正交，不合并

---

## 六、结论

**用户假设"财报 > Wind > anysearch/tavily"在内容真实性维度完全正确；在数值锚定维度，
架构应补充"Wind 为唯一数值真源、财报提取为交叉印证"的分工（P0-B2 已实现）。**
归一性已由 canonical.py 单源契约解决。当前链路实际是"财报（内容）+ Wind（数值）"双源，
搜索未启用；若要启用，按上述"行业/外部补充"定位注入即可。
