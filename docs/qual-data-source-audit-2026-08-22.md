# qual 数据源合规性架构自查报告（2026-08-22）

> 审计原则：**所有数据应来自 Wind（财务权威）和财报解析（事实/运营权威），LLM 不应自己生成数据**。
> 本报告全面自查架构是否遵循此原则，标记合规/违规/残留风险。
> 审计方式：全代码数据流溯源（每个数据产生点 → 来源判定）。

---

```

│  └─ 财报 PDF ────→ MinerU 解析 → sections/tables（原文）             │
└──────────────────────────┬──────────────────────────────────────────┘

        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼

│ Wind 100%    │  │ 财报原文源     │  │ Wind 数据程序算  │
└──────┬───────┘  └───────┬────────┘  └────────┬─────────┘
       │                  │                    │
```

## 二、逐类审计结果

### A. 财务数字（营收/利润/资产/现金流）—— ✅ 合规

| 环节 | 来源 | 判定 |
|------|------|------|
| Wind 三表提取 | Wind MCP | ✅ 外部数据源 |
| DataAnchor 锚点 | Wind（init_from_wind_data） | ✅ 财务 100% Wind |
| fact_extractor 财务填充 | Wind 处置表（resolve_financial_from_wind） | ✅ B2b-1 明确"财务 100% Wind" |
| LLM 提取财务 | **prompt 规则 6 禁止**（"不要提取财务数字——财务 100% 以 Wind 为准"） | ✅ 已禁止 |
| LLM 写作财务数字 | **PGNB 占位符**（[{{营业收入}}] → 程序回填 767.20） | ✅ 已移出 LLM 职责 |
| 裸数字拦截 | validate_bare_numbers（幻觉 14.0 → 触发重试 fail-closed） | ✅ v2 硬约束 |

**结论**：财务数字全链路来自 Wind，LLM 无生成路径（PGNB v2 后）。

### B. 运营/事实数据（DAU/GMV/ARPU/交付量/市占率）—— ⚠️ 有条件合规

| 环节 | 来源 | 判定 |
|------|------|------|
| 运营数据提取 | **LLM 从财报原文提取**（fact_extractor，财报源） | ✅ 源=财报（非 LLM 自造） |
| 提取约束 | 规则 1"只提取财报明确写出的"、规则 5"宁可缺失不可杜撰"、来源章节标注 | ✅ 防编造 |
| 提取后验证 | validate_numerical_ranges（数值范围）+ validate_operational_chain（MAU≥DAU≥付费） | ✅ 程序验证 |
| 运营数据进报告 | 事实表引用（财报源）+ P1-5 标注"未经 Wind 锚点校验" | ⚠️ 诚实标注但无 Wind 交叉 |

**结论**：运营数据源=财报原文（合规——财报是第二权威源），LLM 是"提取器"非"生成器"，且有来源标注+范围验证+结构铁律三道防线。**残留风险**：运营数据无 Wind 交叉验证（Wind 不提供 DAU/GMV），依赖 LLM 提取忠实度——已显式标注。

### C. 估值链参数（WACC/增长率/目标价）—— ✅ 程序计算（非 LLM）

| 参数 | 来源 | 判定 |
|------|------|------|
| 营收增长率 | Wind 营收 3 年 CAGR 程序计算（extract_dcf_params） | ✅ Wind 源+程序算 |
| FCF | Wind OCF - Capex 程序计算 | ✅ Wind 源+程序算 |
| β / rf / erp | **程序常量**（β=1.2 默认，P0-5 已标注降级） | ⚠️ 非 Wind 源但**非 LLM 生成**，已显式标注+敏感性提示 |
| 净负债 | None（P0-4 弃用启发式） | ✅ 诚实未披露 |
| 目标价/DCF | valuation_engine 程序计算（亏损 fail-fast） | ✅ 程序计算 |
| 可比公司 | 静态池（P0-6 标 static_snapshot） | ⚠️ 静态快照，已标注 |

**结论**：估值全部**程序计算**（Wind 数据 + 公式），LLM 不参与参数生成；β/可比是程序常量/静态池（非 LLM），已显式标注局限。

### D. 投资判断（评级/看多看空/结论）—— ✅ LLM 判断（合理例外）

| 环节 | 来源 | 判定 |
|------|------|------|
| 投资评级 | LLM 决策章生成（看多/看空/中性） | ✅ **判断类**（LLM 合理职责——不是数据，是分析结论） |
| 评级-估值一致性 | gate6 程序校验（P1-3 修复后真实触发） | ✅ 程序校验 LLM 判断 |
| 目标价 | 程序计算（非 LLM） | ✅ |

**结论**：投资评级/判断是**分析结论**（LLM 合理职责），非"数据"——但受程序校验（评级-估值一致性、红队审查）。

### E. 写作层（Gate3 章节）—— ✅ PGNB 后合规

| 输入 | 来源 | 判定 |
|------|------|------|
| Wind 锚点表 | data_anchor（Wind） | ✅ 程序注入 |
| 事实表 | fact_extractor（财报源） | ✅ 程序注入 |
| 财报原文片段 | ctx.filing.sections（财报源） | ✅ 程序注入 |

## 四、架构合规性判定

**原则遵循度：财务数据 ✅ 100% 遵循；事实/运营数据 ✅ 有条件遵循（财报源+三道防线）；估值 ✅ 程序计算；判断 ✅ LLM 合理职责（受程序校验）。**

核心架构已符合"LLM 不生成数据"原则：
1. **数据层**：Wind（财务）+ 财报原文（运营/事实）是唯一事实来源，程序提取/计算
2. **LLM 层**：只做结构/表述/逻辑/判断，**数字引用全部占位符回填**
3. **校验层**：ADVC 签名修复 + PGNB 裸数字硬拦截 + 校验器 fail-closed（LLM 若违反立即拦截）

**一句话**：本架构已经从"LLM 自由生成数据"演进为"**数据全由 Wind/财报程序化供给，LLM 只做分析与表述，数字引用经 PGNB 程序回填，任何 LLM 越界数字被三层校验拦截**"——符合用户要求的原则。残余风险均为 Wind 数据源本身不提供的能力（运营指标/个股 β/实时可比），已诚实标注并给出 v3 演进路径。
