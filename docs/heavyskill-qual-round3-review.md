# HeavySkill K8 三方专家审查结论（2026-08-22）

## 一、问题优先级排序

| 优先级 | 问题 | 统一判断 |
|---|---|---|
| **P0** | **P5 跨章一致性 28-77 issues** | 同一指标在不同章节出现不同财年/口径/数值，直接破坏估值模型与投资结论可信度。**不可发布**。 |
| **P0** | **P6 事实核查 score=0, 19 issues** | 必须逐条分类（数据错误 vs 口径差异 vs 表述差异 vs 标准过严），不能直接降门槛。 |
| **P0** | **P4+P11 日期锚点循环与收敛早停** | 审查无法收敛导致全流程无法稳定产出。P11 是 P4/P5/P6 的下游表现，合并治理。 |
| **P1** | **P7 Gate1 FY2023 NoneType** | 若确认导致事实表污染或跨章缺失则升级 P0。 |
| **P1** | **P12 Gate3 gate_issues=1 重试** | 需拿到具体 issue payload 区分格式/结构/数据问题。 |
| **P1** | **P10 DeepSeek Connection error** | 应增加重试/指数退避/备用模型降级通道。 |
| **P2** | **P13 ADVC T3 值类问题不修复** | 最终报告必须显式标注"低置信/需人工复核"。 |
| **P3** | 长期：ADVC 覆盖扩展、黄金回归集、监控指标体系 | 非本周发布阻塞项。 |

## 二、技术方案审查意见

### 方案 A：日期锚点程序化替换 bind_fuzzy_dates — 有条件通过
- **可行**：与 bind_bare_numbers 架构一致，确定性拦截后修复
- **必须调整**：
  1. 不能全局 regex——必须限定**财务语境**（句中有财务指标/FY 年份/同比/环比时才替换）
  2. 增加**否定词典**："当前宏观环境""目前行业竞争"等不得替换
  3. 年份感知：不能一律替换为 FY{latest}，需根据上下文判断是本期还是上年
  4. 无法确定时保留原文标记"模糊时间词待复核"
  5. 执行位置：Gate3 生成后 / patch 后 / Gate8 终局前；在单调性守卫前运行

### 方案 B：单调性守卫豁免日期问题 — 不推荐单独采用
- 会让"当前业绩"与"FY2025 业绩"混用，削弱守卫保护
- 只能作为 A 之后的**软守卫补充**：日期 issue 不触发整体回滚，但进入"日期问题专用处理流程"

### 方案 C：审查修复收敛保障 — 可行且必要
- **max_repair_rounds=3** 合理，但更优策略是"连续无有效修复即停"
- 早停后切换到**确定性终局救援模式**（非"跳过审查"）
- Gate8 终局必须执行：ADVC + PGNB + bind_fuzzy_dates + 跨章一致性检测 + 硬校验
- 终局后仍有 P0 级问题 → 阻断输出转人工复核，不能让 Gate8 变"问题垃圾场"
- 输出 rescue report：已修复/未修复/降级/需人工复核

### 方案 D：跨章一致性程序化修复 — 方向正确，必须升级
- **不能裸数字全局比对**——必须记录：指标名、财年、数值、单位、口径、章节、上下文
- 仅白名单财务指标 + 高置信映射到 DataAnchor → 替换为占位符统一回填
- 禁止替换：不同口径（归母净利润 vs 净利润）、不同单位（元/万/亿）、派生指标、无法确认财年
- 低置信冲突只标注 CrossChapterIssue，输出人工复核清单

## 三、实施顺序

### 阶段 0：快速诊断（不写大代码）
取得关键样本：P5 矛盾明细 / P6 19 条 issue 逐条分类 / P4 模糊词样本 / P7 stack trace / P12 gate payload / P10 错误频率

### 阶段 1：恢复管线可收敛
1. 实施方案 C：早停 + Gate8 终局救援
2. 修复 P7：fact_extractor 防御性 get
3. 处理 P10：重试/退避/降级
4. 建立 rescue report 输出

### 阶段 2：日期语义治理
1. 实施上下文感知方案 A
2. 日期问题改为软守卫（不触发整体回滚，但进日期终局闸门）
3. 重跑验证 P4/P11 收敛

### 阶段 3：跨章一致性治理
1. 根据阶段 0 分类实施 D 的"检测版"
2. 高置信替换为占位符；低置信只标注
3. 第 5/6 章试点后全报告覆盖

### 阶段 4：事实核查校准
1. P6 19 条分类：硬数据错误 / 口径差异 / 表述差异 / 标准过严
2. 硬数据错误走 ADVC/PGNB 自动修复；表述差异降级为 warning
3. 调整事实核查器输出结构化 issue 类型

### 阶段 5：回归与披露
1. P12 gate payload 定位
2. P13 显式标注 ADVC T3 未校正值
3. 建立 golden report 回归集
4. 正负例测试 + 监控指标体系

## 四、核心原则

> **所有自动替换必须可审计、可回滚、有正负例测试，不能以"全局 regex + 静默替换"的方式引入新的语义错误。**
