## 三、数据精确性分级表（买方视角）

### 必须精确（P0——同财年容差 ≤1%，任何偏差=阻断）
- **利润表**：营业收入/营业利润/归母净利润/净利润/毛利率/净利率 → Wind canonical（唯一）
- **现金流量表**：经营/投资/筹资现金流、FCF（含 ΔWC）→ Wind
- **资产负债表**：总资产/负债合计/归母净资产/所有者权益/现金/有息负债 → Wind
- **估值输入**：股本、股价、市值、PE/PB/PS、EPS/BVPS、每股股息/回购、汇率 → Wind quote **动态取**
- **DCF 参数**：FCF/WACC/g/净债务/股份数/EV→每股桥接 → 程序计算
- **运营核心**：MAU/DAU/付费用户/ARPU/ARPPU/交付量/毛利率/分部收入 → 年报事实表+交叉验证
- **语义锚**：财年标签、正负号、币种、同比/CAGR、大股东/管理层持股、回购分红 → Wind+事实表

### 可容忍近似（标注来源+基期+区间，±5-10%）
- 行业规模/增速/用户规模（机构口径）——**必须标注数据年份并与公司财年对齐**
- TAM/渗透率/份额、竞争格局定性、汇率固定值（显式标注）、管理层指引区间

## 四、事实提取表改进方案

### 4.1 字段设计（现状 → 目标）
现状字段：指标/口径/FY/单位/来源（财务行来源硬编码"财报原文"）。
**目标字段**：
```
指标(canonical键) | 指标原文表述 | 财年FY | 数值 | 原文单位 | 归一单位
口径(IFRS/Non-IFRS/经调整) | 正负号 | 来源章节 | 页码
原文片段(≤80字) | 置信度(high/medium/low/unverified)
Wind仲裁状态(matched/overridden/reference_only/na) | 对比期标注
```
关键增补：**页码**（买方复核第一动作是翻原文）、**原文片段**（可程序化 grep 复核）、**置信度**（把 LLM 不确定显性化）、**仲裁状态**（每个字段留痕）、**多财年列**（3 列 FY2023/24/25）。

### 4.2 提取前：章节/段落选择策略
- 弃纯数据密度评分；取章节白名单（港股=董事会报告/MD&A/业务回顾/分部资料/股东回报/风险因素；A股=经营讨论/分部/募集资金；10-K=MD&A/Business/Note to FS）
- **附注仅用于财务，走 MinerU tables 结构化提取，不经 LLM**
- **多年度**：每份年报独立提取（各自 fiscal_year 锚定）→ 3 张单年表合并；禁止混合文本单 FY 提取

### 4.3 提取中：让 LLM 标注不确定度而非猜测
- "宁可缺失不可杜撰"写进 EXTRACTION_PROMPT：未找到→null+注明"未披露"；无法确认财年→FY?；不确定→confidence=low；**禁止用常识补值、禁止用前一批次值补当前批次**
- 输出结构升级为 `{value, fy, unit, basis, page, quote, confidence}`
- 批次一致性：冲突时保留 confidence 高/原文可复核者，冲突写入 meta.warnings

### 4.4 提取后：交叉验证策略（含无 Wind 锚点的运营数据）
- **Wind 交叉验证扩展**：从仅 net_profit/revenue 扩展到全部 canonical 财务字段（≤1% 保留/>1% 覆盖+warning/异财年降级）
- **运营数据验证链**：①原文片段正则复核（数值必须物理存在）②多批次一致性 ③交叉披露（公告/纪要/新闻）④派生钩稽（毛利率=毛利/收入；DAU×ARPU≈收入；MAU≥DAU≥付费用户；ARPPU≥ARPU）⑤超范围值**标注不修正**（现 normalize_units ÷100/×100 是危险的自作主张）
- **删除行业默认值填充**（_calculate_unit_economics 毛利率默认 50% 必须删除）

### 4.5 数值主源边界的专业判断
**财务数字应 100% 来自 Wind，LLM 不再提取三表财务**。理由：
1. 财务可机器获取，LLM 提取边际价值≈0、边际风险=118% 偏差（实证）
2. 年报提取只保留定性/运营/治理/风险/股东回报
3. 事实表财务字段降为交叉印证角色

## 评审总结

**框架本体达标**：11 章结构与买方标准框架吻合；数据源权威契约（Wind 数值锚/filing 内容源/search 补充）方向正确；R5→R7 校验体系已验证收敛（25→5→2 Critical）；canonical 单源+财年锚定+事实表仲裁是业界正确的三件套。

**必须改进的三大结构性缺口**：
1. **"当期财年"语义只有 prompt 铁律、无代码校验**（R6 ch5/ch7 仍锚 FY2024 出厂）
2. **估值/目标价无程序化落地**（ch7 DCF 为 LLM 散文、翻转阈值 428 亿、ch10 无目标价数字）
3. **shadow 模式让校验器只记录不阻断**

共同特征：**把信任押在 prompt 文字纪律上，校验未从"记录"升级为"阻断"**。

---

最终答案：**框架达标需改进** —— 11 章结构与数据源权威契约本体达标且 R5→R7 校验体系已验证收敛，但"财年当期语义代码化、估值程序化、Gate8 阻断化"三大结构性缺口未闭环。
