## 核心发现（ROI 实验数据）

| 层 | 工具型缺陷（导入/密钥/语法/格式） | 业务语义缺陷（边界/控制流/模式） | 真实样本合计 |
|----|-------------------------------|-------------------------------|-------------|
| 门禁单独（L1_LITE） | 100% | 0% | **25%** |
| 门禁 + 评审（heavyskill K=8） | 100% | 100% | **100%** |

- 合成轮 100% 拦截是虚高（缺陷都是工具型）
- 真实轮 25% 才是门禁真实拦截力（业务缺陷逃逸）
- heavyskill 评审对 3 个业务缺陷 3/3 发现（P0 致命 + P1 + P1，8 轨迹收敛）

## 标准实践（已沉淀为 gate_2_2 准出）

**分层原则**：
1. **门禁层**：L0-L3 门禁拦截工具型缺陷——自动化、即时、廉价（秒级-分钟级）
2. **评审层**：业务缺陷评审拦截语义缺陷——需语义理解，静态无能力（分钟级-小时级）
3. **组合**：核心/高风险变更两者都要；低风险变更门禁即可

**执行**（scripts/business_review.py）：
```bash
# 对核心/高风险变更跑业务评审
python workflow/scripts/business_review.py --files "a.py,b.py" --dir .
# 或 dry-run 只看评审包
python workflow/scripts/business_review.py --files "a.py" --dry-run
```

**gate_2_2 准出**：business_review 检查器验证——独立评审记录
（kind=independent，verifier 外部非 agent），notes 含缺陷发现。

## 通用教训

- **合成样本会高估工具价值**：ROI 实验必须含真实项目样本校准
- **门禁与评审分工**：工具型靠门禁（自动化/即时），业务型靠评审（语义/昂贵）——互补非替代
- **业务缺陷常伪装成"能通过检查"**：负数 truthy、return 语义错误、正则漏匹配——静态检查全绿但业务错误
- **独立评审的价值**：heavyskill 8 轨迹 + 审议能发现并裁决严重度分歧（P0 vs P1 合理收敛）
