## 方法论教训（本次实验发现，最重要）

1. **修复循环是 ROI 实验的必要组件**：V1（单次执行）缺陷逃逸 HGF=基线=5，无差异；V2（拦截→修复→复跑）HGF=2 vs 基线=4，差异显现——**门禁价值 = "拦截 + 报告驱动修复"的循环，不是单次检查**
2. **对照必须隔离**：每任务独立 workdir（C1）；ABBA 交替（C4）；计时仅执行段（C5）
3. **门禁能力依赖测试质量**：logic-bug 逃逸证明——门禁拦缺陷的前提是测试覆盖了该缺陷场景
4. **门禁级别配置决定拦截范围**：unpinned-dep 逃逸——OPTIONAL 门禁在 L1 不执行，想拦需提升级别

## 下一步（可执行的 ROI 提升）

1. **轻量分级纳入实验**：当前 HGF 组跑 L2 全量（246s），实际 V3.4-B 轻量分级（L0_LITE/L1_LITE）可降耗时——下次实验应对比 L2 vs L1_LITE 的耗时/拦截
2. **提升 pin-check 级别**：把依赖未固定从 OPTIONAL 移到 SHOULD_PASS（L1 即跑）
3. **任务集扩展**：5-10 个任务，覆盖更多缺陷类型（XSS/注入/竞态/资源泄漏），提高统计置信度
4. **多次运行取均值**：当前单次运行，应多次（3-5 次）取均值 + 报告方差

## 通用教训

- **单次执行测不出门禁价值**：对照实验必须含"拦截→修复→复跑"循环
- **对照组不修复是正确设计**：基线组缺陷常驻，才能对比出门禁的修复驱动价值
- **数据比自证有力**：首次用实验数据（非"门禁全绿"自证）回答"值不值得用"
